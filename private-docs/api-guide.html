接入约定

服务地址
https://halls.z4ck.dev
传输
HTTPS；JSON 使用 UTF-8
文件上限
15 MiB（15,728,640 字节）
时间
Unix 秒；时长字段以秒为单位

在管理控制台的访问设置中开启成绩上传和 API Key 上传，再生成对应用途的 Key。

凭据传递方式权限
上传 Key路径中的 {key}/api/submit/…
KOH Key路径中的 {key}/api/koh/…
查询回执Authorization: Bearer {receipt}仅查询对应提交
管理会话HttpOnly Cookie；写操作另带 CSRF 头管理接口、完整报告和本文档

Key 明文仅在创建时返回一次。撤销可恢复，恢复后继续使用原 Key。Key 和查询回执互不替代。调用程序请发送明确的应用名称，例如 User-Agent: HALLS-API-Client/1.0。

Key 位于 URL 中。部署时通过环境变量注入，避免记录完整请求地址。公开页面不提供 API 文档或原始凭证下载。

提交成绩

POST/api/submit/{key}

请求体直接发送原始 .hproof 字节，不使用 multipart。服务端完成校验、评判与发布策略处理。

位置 / 名称类型要求
path · keystring有效的上传用途 Key
query · namestring必填；规范化后 1–32 个字符，无控制字符，URL 编码
query · waitnumber可选；0–10 秒，默认 0
header · Content-Typestringapplication/octet-stream
header · X-Proof-SHA256string可选；64 位小写十六进制。服务端重新计算并核对
header · X-Source-IDstring可选；来源编号、靶机 Host 或网址，最多 256 字符，仅后台可见
bodybinary308 字节至 15 MiB；正式提交仅接受 HLR5 / 0.11.3

请求示例

HALLS_API_KEY='YOUR_UPLOAD_KEY'
export HALLS_NAME='Player'
NAME=$(python3 -c 'import os,urllib.parse; print(urllib.parse.quote(os.environ["HALLS_NAME"]))')

curl --request POST \
  "https://halls.z4ck.dev/api/submit/${HALLS_API_KEY}?name=${NAME}&wait=0" \
  --user-agent 'HALLS-API-Client/1.0' \
  --header 'Content-Type: application/octet-stream' \
  --header 'X-Source-ID: YOUR_INSTANCE_HOST' \
  --data-binary @victory.hproof

保存响应中的 receipt，它仅在本次响应中提供。

响应

202：已接收，继续查询。设置 wait 且处理在等待期内结束时返回 200。

{
  "id": "0123456789abcdef01234567",
  "status": "queued",
  "receipt": "YOUR_SUBMISSION_RECEIPT",
  "statusUrl": "/api/submissions/0123456789abcdef01234567",
  "report": null,
  "message": "携带 receipt 轮询 statusUrl 可获取完整报告；请保存回执。"
}

重复文件返回 409 / duplicate_hash，不会复用已有成绩或返回其回执。

上传前检查摘要

POST/api/uploads/check
{ "sha256": "64 位小写十六进制摘要" }

// HTTP 200
{ "duplicate": false }

该接口不要求 Key，只返回是否已有同文件摘要，不提供成绩或回放。它用于减少重复传输；实际上传仍会再次检查。KOH 接入使用下方的专用预检接口。

查询结果

GET/api/submissions/{id}
curl 'https://halls.z4ck.dev/api/submissions/0123456789abcdef01234567' \
  --user-agent 'HALLS-API-Client/1.0' \
  --header 'Authorization: Bearer YOUR_SUBMISSION_RECEIPT'

建议间隔 2–5 秒轮询，进入终态后停止。回执仅能查询对应记录；不存在的记录和无效回执均返回 404。

字段含义
id / name记录编号、展示名字
status接收与评判状态，见下表
decision / board审核决定与发布位置
score / referenceScore0–100 分；未完成时可为 null
duration / completedAt记录用时、通关 Unix 时间
platform / architecture平台与编译架构
created / updated服务端接收、更新时间
verdict / report评判结论、完整报告；未完成时 report 为 null
playable / tags回放是否可用、成绩标签
status含义继续轮询
queued / processing排队 / 正在评判是
done评判完成否
invalid认证或格式校验失败否
duplicate同一通关记录已存在否
error评判未完成，需要管理员处理否

decision 为 pending、approved、rejected；board 为 hidden、ranked、unranked。HTTP 成功、文件有效、评判通过和公开展示是不同状态。最终展示位置以查询接口顶层字段为准。

报告结构

上传 Key 提交对应的回执，以及管理会话，可以读取完整报告。普通网页回执与公开成绩只返回文字化报告。

字段内容
reportVersion / generatedAt报告版本、生成时间
verdict / labelaccepted、accepted_limited、review、rejected、not_assessed 及文字说明
importChecks封装、认证、解压、签名、格式检查结果
rules各项检查：id、title、status、reason、checked、violations，以及私有证据
failed / review / disabled / insufficient各状态的检查编号列表
proof / metrics记录摘要与运动、计时、战斗统计
bot行为特征与自动化相似度
performancescore、referenceScore、grade、components、adjustments 与成绩评价
policy / platformPolicy评判与发布时使用的策略快照
engine / coverage / limitations评判覆盖范围、引擎信息与适用限制

认证、格式失败不能视为有效成绩。有效通关成绩按通关、竞速、金币、战术与评判调整计算；ranked 和 unranked 均可计分。具体权重由管理员配置，接入方应使用返回分数，不在本地重算。

规则证据为有上限的展示样本，不代表只检查这些帧。行为相似度是复核线索，不能视为作弊概率。

KOH 赛事接入

使用 KOH 用途的 Key。容器先检查摘要，再上传文件，最后轮询分数。Key 由部署配置注入，不向选手网页返回。

  1. 本地计算 SHA-256 和文件字节数。
  2. 调用 lookup，判断是否需要传输。
  3. uploadRequired=true 时上传，否则直接处理返回结果。
  4. 轮询 results，向赛事平台返回 0–100 的原始分数。

1. 摘要预检

POST/api/koh/{key}/lookup
{
  "sha256": "64 位小写十六进制摘要",
  "bytes": 123456,
  "instance": "0123456789abcdef0123456789abcdef",
  "context": { "problem_id": 42, "submission_id": 7 },
  "source_id": "YOUR_INSTANCE_HOST",
  "source_kind": "configured"
}
字段要求
sha256 / bytes必填；声明原文件摘要与大小，1 字节至 15 MiB
instance必填；容器启动生成的 32 位小写十六进制标识
context仅含 problem_id、submission_id；正整数，小于 2⁶³
source_id可选；私有来源标识，最多 256 字符
source_kind可选；configured、context、page_host、request_host、forwarded_host、provided、unspecified
// 需要上传 · HTTP 200
{ "known": false, "status": "awaiting_upload", "uploadRequired": true }

// 已被其他提交使用 · HTTP 200
{
  "known": true, "status": "done", "uploadRequired": false,
  "result": { "code": 200, "score": 0, "max_score": 100,
              "feedback": "凭证已被提交，本次得分为 0。" }
}

同一 Key、题目编号和提交编号绑定同一份文件；修改绑定的摘要或大小返回 409 / submission_conflict。相同提交重试可查询自己的处理结果，其他提交使用相同凭证直接得到 0 分。

2. 上传凭证

POST/api/koh/{key}/proofs/{problem_id}/{submission_id}
Content-Type: application/octet-stream
X-KOH-Instance: 0123456789abcdef0123456789abcdef

请求体：原始凭证字节

必须先通过 lookup。字节数与摘要必须匹配预检记录。可带查询参数 name；默认展示名为 KOH #{submission_id}。首次接收返回：

// HTTP 202
{ "status": "queued", "uploadRequired": false,
  "id": "0123456789abcdef01234567" }

3. 查询分数

GET/api/koh/{key}/results/{problem_id}/{submission_id}
// HTTP 200 · 完成
{
  "status": "done", "uploadRequired": false,
  "id": "0123456789abcdef01234567",
  "result": { "code": 200, "score": 68.45, "max_score": 100,
              "feedback": "成绩与回放：https://halls.z4ck.dev/run/…" },
  "runUrl": "/run/0123456789abcdef01234567"
}

排队和处理中返回 status=queued/processing，没有 result。服务或评判故障返回 503 与 status=error，不能记为选手 0 分。无效或重复凭证的完成结果为 0 分。成绩按全自动审核进入 ranked 或 unranked。

容器网页后端对新提交限制为每 60 秒一次，赛事提交重试使用同一编号。建议赛事评测超时设置为 120 秒。

公开数据与回放

成绩报告的 performance.raceReference 提供保存的竞速参考时间。GET /api/runs/{id}/race-reference 按记录可见性提供参考路线的世界坐标，最多 8192 点；近似值标记 approximate=true。参考固定为出生点直奔原始出口，不为金币绕路，读取不会重新评判。

GET/api/runs?board=ranked&sort=score&page=1&q=Player

board：all（默认积分总榜）、ranked 或 unranked；sort：score、speed、recent；page：1–1000；q：最多 32 字符。总榜合并已公开的两类记录后统一排序、分页，每页最多 25 条；每条记录保留 board，并提供用于排序和展示的 displayScore；rank 只对 RANKED 按当前排序计名次，在搜索和分页前计算，UNRANKED 的 rank 为 null，不占名次。返回 items、total、page、pages、stats、boards、board、boardCounts。

GET/api/runs/{id}

只对已公开记录提供详情与文字报告。可播放的公开记录带 replayBase；展示回放为平台二进制数据，不包含原始凭证。

GET{replayBase}/manifest.bin

公开回放使用独立 CDN 路由，无需认证；资源可能随下架撤回，客户端应使用详情返回的地址，不拼接版本摘要。

未公开成绩的管理回放和独立预览使用私有接口、短期票据与 Cookie，不经过公开 CDN。独立预览由本站 /preview 操作，转换后只保留展示数据和原文件摘要，不创建成绩。

GET/api/downloads

返回 items 与空状态提示。开放下载时，清单包含平台、架构、文件大小与 SHA-256；游戏下载关闭时文件直链返回 403。

GET/download=halls?platform=windows&arch=x86_64

平台：windows、macos、linux。架构以下载清单为准，不支持的组合返回 404。

管理员通过本机独立服务的 /admin 访问后台。公开服务不提供后台入口。

管理接口

除文件上传外，写请求需 Content-Type: application/json，并在 X-CSRF-Token 中携带 session 返回的 csrf。

POST /api/admin/runs/{id}/rejudge按当前规则重新评判并暂时下架
GET /api/admin/runs/{id}/report下载完整 JSON 报告

GET / POST /api/admin/keys列出 Key 摘要；创建请求 {"label":"名称","scope":"upload"}，scope 可为 koh；返回 id、key
POST /api/admin/keys/{id}/revoke

来源标识、容器实例和赛事提交编号仅用于后台核验，公开详情、成绩列表与回放均不返回这些字段。CSV 时间为 UTC，文件摘要预检记录可标为尚未核验。

错误与重试

{ "error": "错误说明", "code": "duplicate_hash" }

接口错误通常为 JSON。上游网络或安全服务可能返回 HTML，应先检查状态码和 Content-Type，再解析响应体。

HTTP含义调用方处理
400 / 415参数、摘要、文件长度或类型无效修正请求，不原样重试
401Key 无效或已撤销检查凭据 / 重新登录
403入口关闭、用途错误、Origin 或 CSRF 不符检查后台设置和请求上下文
404不存在、未公开、管理会话失效或回执不可用检查编号与凭据
409重复摘要、提交绑定或策略版本冲突停止重复上传；读取最新版本后处理冲突
413文件超出大小限制不重试同一文件
429频率、队列或访问额度限制遵循 Retry-After，退避并加入随机延迟
500 / 503服务、容量或评判暂不可用保留原提交信息，稍后查询；不要换编号反复上传

当前默认：普通 API 上传每 Key 与每 IP 每小时 60 次；网页成绩上传每 IP 每小时 6 次；总接收和处理队列上限 8 个。KOH API 每 Key 每分钟 600 个请求；新提交频率由容器网页后端限制。限流和存储配额可随部署调整。

认证失败的报告可能额外包含 stage、checks、importAccepted=false。即使签名通过，结构或数据校验失败仍是无效文件。
